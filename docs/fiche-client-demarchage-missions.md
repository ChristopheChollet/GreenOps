# Fiche client — démarchage, messages & cadrage mission

Document personnel : tout ce qui touche au **terrain commercial** (LinkedIn, qualification, proposition, validation, admin).  
À utiliser en parallèle de la roadmap technique : [Roadmap compétences — 12 mois (niche climat)](roadmap-competences-12-mois-niche-climat.md).

---

## 1. Consignes pour démarcher (ce qui marche en pratique)

- **Personnalisation obligatoire** : 1 phrase minimum qui montre que tu as lu **leur site / produit / annonce / post**.
- **Court** : ton interlocuteur lit vite ; éviter les romans.
- **Une intention claire** : pas « je suis dispo », mais **POC / renfort / lot court**.
- **Preuve en une ligne** : GreenOps + GreenChain + stack (sans jargon inutile).
- **CTA simple** : « 15–20 min cette semaine ? » + proposition de créneaux ou « répondez oui/non ».
- **Pas harceler** : **1 relance** après **5–7 jours** si silence.
- **Pas inventer** : pas de promesse d’embauche / date / chiffre ; tu proposes **périmètre + étapes**.
- **Alignement statut** : si ça devient sérieux (**budget / signatures**), tu clarifies **freelance / facturation micro** (sans tout déballer au premier message).

## 2. Messages types (à adapter à chaque fois)

### A) Demande de connexion + note (si LinkedIn impose une note courte)

```

J’ai deux livrables publics (GreenOps / GreenChain). Je vous contacte car [phrase précise]. Si vous avez un POC ou un renfort court, je serais ravi d'échanger 15 min.
```

```
Bonjour [Prénom],

Je suis développeur full-stack basé à Toulouse : je livre des MVP/démos SaaS (Next.js, TypeScript, Supabase, Vercel) sur des sujets énergie & climat ; Web3 (Solidity/wagmi) uniquement si le cas métier le justifie.

Christophe
```

### C) Relance douce (silence)

```
Bonjour [Prénom], petite relance : seriez-vous ouvert à un échange court sur un POC / renfort Next.js ? Si ce n'est pas le bon timing, aucun souci — bonne continuation.
```

## 3. Étapes pour cadrer une mission (du premier échange à la validation)

### Étape 1 — Qualifier vite (**≤ 15 min** au téléphone / visio)

**Objectif** : savoir si tu dois **continuer** ou **arrêter**.

Questions minimales :

- **Problème / résultat attendu** : « À la fin, qu’est-ce qui doit être vrai ? »
- **Utilisateurs** : qui utilise le produit ? interne / externe ?
- **Contraintes** : délais, budget ou fourchette, conformité (**RGPD** basique), intégrations existantes.
- **Décision** : qui valide ? qui signe ?
- **Stack / contraintes tech** : existant vs greenfield.
- **Accès** : repo, design, analytics, comptes (**après signature** ou après accord).

### Étape 2 — Reformuler par écrit (mail ou LinkedIn)

Tu renvoies un mini-résumé :

- objectif  
- hors-scope évident  
- livrables  
- durée indicative  
- risques / dépendances (accès, contenus, validation client)

→ évite une grande partie des disputes.

### Étape 3 — Proposition commerciale (même simple)

Minimum utile :

- **périmètre** (liste de fonctionnalités / écrans / endpoints)
- **méthode** (ateliers légers si besoin, cycles de livraison)
- **planning** (jalons)
- **prix** : **TJM × jours** ou **forfait** si très clair
- **modalités** : acompte éventuel, délais de paiement, clauses simples

### Étape 4 — Validation (« Go ») avant code sérieux

Tu attends au minimum :

- accord écrit sur **le lot** (même un mail « OK pour la proposition du … »)
- identification du **validateur**
- date de **kick-off**

### Étape 5 — Facturation / admin (quand tu es prêt)

- mentions légales / **RIB**
- calendrier de facturation (fin de lot / fin de mois)

## 4. De quoi parler pour être choisi comme prestataire

Tu ne « vends » pas ta passion : tu **réduis le risque** pour le client.

Souvent décisif :

- **Clarté** : bonnes questions + reformulation.
- **Découpage** : premier **lot court** plutôt qu’un tunnel infini.
- **Preuve** : démo + GitHub + captures ; tu expliques **ce qui a été livré**, pas la techno pour elle-même.
- **Communication** : disponibilité, délais de réponse, points réguliers.
- **Propreté** : README, doc courte, **recette** (« validé quand… »).
- **Transparence** : junior OK si pas de mensonge sur l’expertise ; sécurité par **périmètre**.

---

## 5. Phrases qui aident à conclure (sans être agressif)

- « Je vous propose de démarrer par un lot de **X** jours pour livrer **A/B/C** ; ensuite on décide de la suite. »
- « Voici ce qui est **inclus / non inclus** pour éviter les malentendus. »
- « Le livrable est validé quand : **[critères mesurables]** »

---

## 6. Avant de te lancer — conseils terrain (court)

- **Rythme soutenable** : créneaux récurrents pour les messages (ex. **45–60 min/jour**), plutôt que pics puis épuisement.
- **Suivi minimal** : tableau (Notion / Sheet) **contact → date → statut → prochaine action**.
- **Personnalisation minimale** : 1 phrase « pourquoi vous » + preuve + CTA court.
- **Relance** : **1 fois**, polie, après **5–7 jours**.
- **Qualification rapide** : si sérieux → **périmètre / deadline / budget / décideur**.
- **Cadre écrit avant code** : livrables + hors-scope + critères « terminé ».
- **Paiement** : idéalement **acompte** si client inconnu ; éviter « 100 % fin + délais flous ».
- **Statut / admin** : anticiper **micro + facturation + IBAN** avant première prestation facturée ; phrase honnête si immatriculation en cours.
- **RSA / aides** : si activité / revenus, anticiper avec les **bons interlocuteurs** (CAF / France Travail selon ton dossier).
- **Logement** : garder le **plan studio ≤ 500 €** actif en parallèle (réactivité + dossier PDF).
- **Outils** : si pas Cursor → **VS Code** + IA en complément (plus de friction qu’un agent IDE).
- **Santé mentale** : normaliser le silence ; **bilan hebdo** (volume / réponses / leçons), pas « je suis nul ».
